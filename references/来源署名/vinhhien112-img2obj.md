## 未吸收（3D 领域执行物，不进正文）

以下内容属该项目的**具体实现物**，本技能一概不吸收：

- Three.js / TypeScript factory 生成代码、`scripts/sculpt.py` 与整套 CLI 契约、`ObjectSculptSpec` 的具体 schema 字段
- PBR 通道工程细节（albedo / roughness / height / normal / AO 的提取与烘焙）
- 拓扑策略、socket / pivot / 父子层级绑定机制、运行时 receipt
- capability packs 的领域内容（植被生成、硬表面、有机皮肤、毛发纤维、织物、透光、地形、程序化运动、发光体积、贴花标记）
- 该项目的 Codex 插件绑定与 `.codex-plugin` manifest

## 需剔除元素（使用本方法学时的自检）

- ❌ 不得把 3D / Three.js 的具体 API、schema 或代码结构写进本技能正文——本技能只留"阶段划分 + 门禁 + 禁止项"这类通用方法学。
- ❌ 不得把"照着图做 3D"当成设计默认路径。**引用判定见下**：若任务实为平面/UI/海报，四阶段与 PBR 概念**不适用**，只取"双评审 + 关键特征否决 + 冠军/挑战者"这套验收机制。
- ❌ 不得因吸收了这套机制就默认该上 3D。是否上 3D 仍由 `02-感知物料/模型.md` 第 1~4 节的选型决策判定（目的 / 类型 / 复杂度 / 交付格式）。

## 边界判断记录（2026-08-31）

- **吸收的是"评审与迭代机制"，不是"3D 本身"。** 用户此前有过负面经验：为追求"可旋转 / 照片级真实感"强行上程序化 Three.js，结果"能转但一看就假"，不如干净的 2D 方案。因此本次吸收按用户要求落在两处：① 通用评审机制进第 5 层验收（任何视觉产出都受益）；② 执行流程只补进 `模型.md`，且限定在"任务确实要照图做模型"时触发。
- **思想层不设限**：双评审、关键特征否决、冠军/挑战者、影响评估均为通用工程/评审技法，非该项目专属，可自由并入。
- **无整体近似度风险**：本技能产出为设计方法学文档，与该仓库的 3D 代码产物不形成观感近似。
