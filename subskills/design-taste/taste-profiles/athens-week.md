## 🟥 二、品味三维度（核心 · 仅用户原话，AI 不增补）

### 档位 vs 模板（用户 2026-09-04 强约束）

- **档位（正确用法）**：这是一组判断准则。接到任意设计任务时，把这组准则**打开**，它从决策层约束每一个设计选择——但**不规定任何具体版式、区块结构或页面骨架**。
- **模板（错误用法，AI 反复犯）**：先预设一个固定页面骨架，再把品味当皮肤贴上去、换图换字。用户原话："**我的品味可不是这样用的**""**你这也只是替换了图片**"。
- 结论：结构/版式必须**跟着内容重新长出来**，每次都不同；三维度只管"判断标准"。

### 1. 排版（Typography）— 用户原话 ✅

> 手写 + 衬线 + 几何无衬线三者混排、左对齐编辑式网格、无大号手写标题

### 2. 交互（Interaction）— 用户原话 ✅

> 以"探索 / 揭示"为核心的交互语言（拖拽聚光、滚动逐层展开、克制微反馈）

- 用户校准补充（同一轮，关于"拖拽聚光"的手感）：聚光必须是**跟随光标的可见光圈**——白膜常驻覆盖内容，光标处一个圆形范围**临时透出**底下内容，移开即重新盖回；**可见范围就是揭示出的物体/图片区域本身**，不叠加任何 UI 指示器（无圆环、无中心点、无十字丝），不要"加一个框框框住"；**绝不能是刮刮乐式永久擦除**（擦掉就消失、不可恢复）。
- **关键补充（2026-09-04 12:44）**：白膜覆盖的是**物体本身的形状**（像石膏像/白模，是物体自己的轮廓被刷白），**不是**整块矩形白幕 + 一个圆形窗口——后者会被用户视为"一框框"。揭示时露出的颜色必须只在该物体形状内；实现上需把物体从背景中抠出（透明轮廓），白膜层只对物体做灰阶提亮，背景仍透出纸面。
- **揭示机制定型（2026-09-04 终校 · 用户原话"我的遮罩和我的图片不应该是两个叠在一起的了吗"）**：
  - **结构 = 两层叠加**：底层 `.layer.film`（白膜，z-index:1，只对物体做灰阶提亮刷白） + 上层 `.layer.color`（彩色本体，z-index:2，完整彩色图）。
  - 上层彩色层默认 `clip-path:circle(0)` 完全裁掉不可见；光标移动时 JS **直写** `clip-path:circle(Rpx at 光标坐标)`，只让光标那一圈透出彩色、圈外仍是白膜；移开 reset 回 0。
  - ⚠️ **实现铁律**：`mask-image` + CSS 变量继承方案在预览环境中反复失效（子元素拿不到变量值 → 揭示静默、用户只见白膜），**定型用 `clip-path` 直写**；它天然就是"两层叠加"结构，契合用户心智模型，**勿回退到 mask-image**。

### 3. 颜色（Color）— 用户原话 ✅

> 暖中性场 + 单一高饱和强调色（蓝）的色彩纪律

- 由此直接推出的两条硬约束：**暖中性底色（非纯冷白）**、**唯一强调色为蓝、不引入第二强调色**。

## 🚫 三、红线（本实例禁用，叠加主技能硬禁令）

- **无额外 UI 指示器**：聚光揭示时不得叠加圆环、中心点、十字丝等任何指示器；可见范围即物体/图片本身（用户："不要加一个框框框住"，"一框框"不可接受）。
- **非刮刮乐**：揭示是临时透出，移开即盖回；**绝不能是永久擦除式**揭示（擦掉就消失、不可恢复）。
- **勿回退 mask-image**：两层叠加揭示必须 `clip-path` 直写实现（见上「揭示机制定型」），不得回退到 `mask-image` + CSS 变量继承方案（预览环境子元素取不到变量 → 揭示静默失效）。
- **不预设固定骨架**：结构/版式须由内容重新长出来，不得先预设骨架再把品味当皮肤贴上去（用户："你这也只是替换了图片"）。
- **不引入第二强调色**：全站唯一强调色为蓝，不得引入第二强调色或 AI 紫/霓虹渐变。
