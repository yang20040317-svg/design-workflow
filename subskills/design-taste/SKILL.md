# design-taste ｜ 独特品味档案容器

> 本技能是 design-workflow 主技能「**模式 2 ｜ 吸睛**」的**本体**——模式2定位"抓眼球 / 强传播 / 强记忆点"，其独特审美判断与反套路手法全部来自这里。
> 核心思想：**独特品味不是单一固定面具，而是一组可演进的审美实例的集合。** 因此本技能是一个**容器（Container）**——定义"一个品味实例长什么样"，并装载用户确认的品味实例（当前仅 `athens-week`：用户显式定义的 排版 / 交互 / 颜色 三维，参考图事实与品味档位分离）。每次生成时**从容器里挑一个**。
>
> **形态：** 容器协议（本文件 schema + 选取/组合规则）内嵌于此；具体实例放在 `taste-profiles/`（每个实例一个 `.md` + 对应参考图）。本文件只定义规则，实例可无限扩展。

## 一、Profile Schema（一个品味实例的必含结构）

`taste-profiles/<profile-id>.md` 必须严格由以下结构组成 —— **三段式是强制形态，不是建议**。

### 1. 元数据（frontmatter，仅标识用）

```yaml
id: athens-week             # 唯一 slug，用作引用键
name: 古典雕塑白膜 / 手写蓝字 / 博物馆编辑页
summary: 一句话气质描述
references:                 # 参考图（实际图片文件，放同目录）或私有链接
  - athens-week-fullpage.png
composable_with: []         # 可与哪些实例组合（混搭白名单）
# 注：可附加 owner_note 等非约束注释字段；以上 id/name/summary/references/composable_with 为约束项。
```

### 2. 正文三段式（强制，缺一不可）

> **原则：品味是「档位」不是「模板」。** 维度严格以**用户显式发送**的为准，AI 不得自行增补任何维度。

- **🟦 第一段 · 参考图事实**：那张图/那个链接里"长什么样"。这是**内容载体（例子）**，可被任意内容替换，**不是品味本身**。须先 Read 打开原图、经用户确认后写。
- **🟥 第二段 · 品味维度**：用户真正的审美准则集合（档位）。**只收录用户显式定义的维度原话，AI 不增补**——用户发几个维度就列几个，没有的维度绝不写。
- **🚫 第三段 · 红线**：本实例额外禁用的手法/配色/元素，叠加主技能硬禁令。

### 3. 标准模板（复制此骨架，填入具体实例）

```markdown
---
id: <slug>
name: <气质名>
summary: 一句话气质描述
references:
  - <参考图文件名或与 .md 同级图片>
composable_with: []
---

> NOTE: 参考图与本文件同级；原图才是第一手事实，档案文字是二手描述。

---
```

## 二、容器目录约定

```
design-taste/
  SKILL.md                 # 本文件（含容器协议）
  taste-profiles/          # 实例容器
    _README.md             # 目录说明 + 如何新增实例
    athens-week.md         # 古典雕塑白膜 / 手写蓝字 / 博物馆编辑页（用户确认品味实例）
    athens-week-fullpage.png
    ...                    # 后续任意新增
```

**规则：**
* 新增品味只需在 `taste-profiles/` 放 `<id>.md` + 参考图，无需改本文件。
* 生成时**必须对照 `references` 里的实际图片**，而非仅凭文字想象。
* 实例数量无上限；容器即"你的独特品味库"。

## 三、选取与组合规则（从容器产出）

1. **默认不锁死**：没有"全局默认签名"。每次按模式 2 的 brief（强传播 / 强记忆点目标）从 `taste-profiles/` 选最匹配的实例。
2. **单一匹配优先**：brief 命中某一气质 → 整实例套用（用户所发维度 🟥 一次性一致）。
3. **组合（composable）**：当 brief 明确跨气质（如"手作但偏杂志排版"），仅允许组合 `composable_with` 白名单里的实例，且**只合并被 brief 支持的维度**，禁止无端混搭。
4. **参考图优先（强制三步，缺一不可）**：
   - **4.1 先读图**：动手前**必须**用 Read 打开 `references` 里的**实际图片文件**。档案 `.md` 里的文字只是"用户口述的二手描述"，**原图才是第一手事实**。
   - **4.2 复述确认**：读图后先用文字**复述"我从这张图里读到了什么"**（主体是什么、什么材质、排版怎么分、白膜/遮罩覆盖哪块、信息块在哪、有没有大标题），**经用户确认后**才动手。
   - **4.3 再动手**：确认后才产出。
   - ⚠️ **反面教训（真实发生过）**：跳过 4.1 只读档案文字，把"白膜 + 穿衣服的人"猜成"白墙上的服饰浅浮雕"，而真实是**一排立体白色古典立像群**——连做两版全废。**任何时候都不得凭档案文字想象视觉主体。**
5. **区分「品味档位」与「参考图内容事实」（强制，2026-09-04 用户纠正）**：一个品味实例档案里必须能分清两类信息，且**绝不可把内容事实当成品味本身**：
   - **品味档位 = 用户定义的品味本体（跨内容都成立）**：维度严格以**用户显式发送的**为准，**AI 不得自行增补任何维度**。例如用户原发 athens-week 只列了 `排版` / `交互` / `颜色` 3 个，档案就只能有这 3 个——即便 AI 觉得"还该有空间/动画"，也**不得写入**（用户原话："不要随便添加，有的就有，没有的就没有"）。这是用户真正要的审美判断，必须由用户显式定义，AI 不得臆造、不得用参考图事实冒充。
   - **参考图具体内容事实 = 某一次的内容载体（可被任意内容替换）**：如"立像数量/材质/白膜范围/某次配色实例"。只是某一个参考图的'样子'，不是品味。
   - ⚠️ **真实翻车案例（同一轮）**：athens-week 档案曾被写成'白色古典立像群 + 材质/颗粒/侧影规格'，大篇幅定义内容，却从未定义用户的排版/交互/颜色品味——产物满屏立像、毫无设计语言，用户判"搞错了重点"。
   - **判别口诀**：参考图是"一个例子"，品味是"跨例子的规律"。立像、材质、白膜都只是例子里的'内容'；而'排版怎么排、颜色怎么守、交互什么手感'（用户发了哪些维度，就列哪些）才是品味。前者可换，后者是用户。
   - 🚫 **致命误用：把档位当模板（用户 2026-09-04 强斥）**：品味是**一组判断准则 dial（档位）**，打开后贯穿所有设计决策，**不规定任何版式/页面骨架**。AI 反复犯的错误是：先预设一个固定页面骨架（如"聚光 hero + 引言 + 索引 + 字体系统 + colophon"），再把品味当皮肤贴上去、只换图换字——用户原话"**你这也只是替换了图片**""**我的品味可不是这样用的**"。正确做法：结构/版式必须**跟着内容重新长出来**，每次都不同；档位只管用户所发维度的判断标准。
6. **冲突裁决**：若组合导致主技能硬禁令冲突（如强调色命中 AI 紫），以主技能为准，回退该维度。
7. **反套路底线**：任何实例都不得滑回"AI 默认观感"（见 design-frontend 反模板校准 A/B/C）。独特 ≠ 通用 AI 味。

## 四、接入模式 2 的约束权重

被「模式 2 ｜ 吸睛」调用时，本容器作为以下层级的**强约束**：
* **第三层 形式组织**：实例的用户维度（🟥，如排版构图）必须贯彻，不得临时换成中性默认。
* **第四层 信息叙事**：强调色与视觉权重沿 profile 的强调色纪律（颜色维度）走，记忆点唯一且一致。
* **第五层 主观输出**：验收时以 profile 的"感觉/情绪"目标为标尺，而非泛泛"好看"。

## 五、容器落地检查（并入模式 2 终检）

- [ ] **已选实例：** 明确声明本次套用 `taste-profiles/<id>`（或组合），而非凭空生成？
- [ ] **对照参考图：** 已用 Read 打开 `references` **实际图片**（不是只读 .md 文字）、并已向用户复述"从图里读到了什么"且获确认？（规则三·4 强制三步）
- [ ] **三段式完整：** 所用实例严格含 🟦参考图事实 / 🟥品味维度 / 🚫红线 三块，无缺失或漂移回旧式 7 字段（colors/shapes/texture/...）？
- [ ] **维度一致：** 套用实例后，用户所发维度（🟥）在全站统一贯彻，未中途混入其他实例未声明的维度？
- [ ] **组合合规：** 若有组合，仅发生在 `composable_with` 白名单且只合并被 brief 支持的维度？
- [ ] **未违反硬禁令：** 实例的 🚫 红线 + 主技能 Section 4 类硬禁令全部满足？
- [ ] **非 AI 默认观感：** 产出未滑回暖米白+衬线+陶土橙等通用默认组合？

## 六、新模式 2 品味吸收规则（链接 / 图片 → 骨架拆解 → 留存品味）

当用户提供**新的链接或图片**作为模式 2 的品味来源时，**必须**走 design-workflow 的「骨架」（五层顺序框架）拆解，不得跳过、不得直接搬运参考源：

1. **先过骨架**：用 design-workflow 五层（场景 → 感知物料 → 形式组织 → 信息叙事 → 主观输出）对链接/图片做拆解，把"那张图/那个站长什么样"沉淀为 `taste-profiles` 里的「🟦 参考图事实」。
2. **提炼档位**：从拆解结果里只抽取**用户显式定义的品味维度**（🟥），AI 不增补任何维度；把内容事实与品味档位严格分开。
3. **留存到品味**：将「🟥 维度 + 🟦 事实 + 🚫 红线」写入 `taste-profiles/<id>.md`，成为可复用的品味实例。
4. **参考源私有**：拆解所依据的链接/图片是**用户私有品味素材**，不是通用可分发资产；design-workflow 骨架可被任何人复用，但**不得把用户的参考源当作通用素材对外提供**。

> **模式 1 / 模式 2 互不干扰**：模式 1（领域适配）走参考站做常规设计、绝不调用 taste-profiles；模式 2（吸睛）走 design-taste 品味基线、参考图仅在模式 2 内生效。两者共用「骨架」，但品味资产与常规设计资产分离。
