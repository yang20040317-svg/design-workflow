# design-ip-assets ｜ 专属视觉资产体系（IP 化）

> 本技能承载 design-workflow 中**缺失的那个维度**：通用方法学（`modules/` 五层）+ 审美方向（`design-taste`）都有了，但"**这是谁的**"还没定义。
> 核心思想：**IP 化 = 一套可跨作品复用、带强识别度的专属视觉资产。** 它不是一次性的好看，而是每次出场都让人认出"这是你的"——角色、符号、配色签名、字体人格、图形语言五位一体。
>
> **与 design-taste 的分工（重要）：**
> - `design-taste` = 审美方向（这张该走暖感 / 杂志感 / 暗黑……调性），是**流动的、按 brief 选的**。
> - `design-ip-assets` = 专属资产（你的角色长啥样 / 你的签名色是什么 / 你的符号是什么），是**固定的、每次都带的**。
> - 二者可同时激活：用 taste 定本次调性，用 ip-assets 保证"调性之下仍是你的脸"。IP 资产优先级高于 taste——taste 可调，资产不动。

## 一、资产类别（5 类，全为可复用硬资产）

| 类别 | 字段文件 | 一句话 |
|---|---|---|
| 1 角色/吉祥物 IP | `assets/character.md` | 跨作品出场的虚拟角色，是 IP 的人格载体 |
| 2 固定符号母题 | `assets/sigil.md` | 专属图形标记（签名式图形元素），一处出现即识别 |
| 3 专属配色签名 | `assets/palette.md` | 只属于你的固定色板，"色即识别" |
| 4 字体人格 | `assets/typeface.md` | 专属字体组合 / 手写签名体，文字也带脸 |
| 5 图形语言 | `assets/graphic-language.md` | 统一的造型语法（圆润/尖锐/手绘感/几何……） |

> 每类一个 `.md`（schema 见下文），资产文件可带实际图（同目录 `<asset>-ref-*.png`）。

## 二、各类资产 Schema

### 1 · 角色/吉祥物 IP（character.md）
```yaml
id: character
name: 角色名
summary: 一句话人格（如"慢悠悠的观察者"）
form:                       # 造型硬约束
  species: 拟人化动物 | 抽象形体 | 人物 | 物件拟人
  silhouette: 圆胖团子      # 剪影特征（远看可认）
  proportions: 头身比 1:1   # 固定比例，不许每版乱变
  key_features: [圆肚, 小短腿, 单眉]   # 不可省略的识别点
color: 主体固有色（须引用 palette.md 的签名色，禁止临时新色）
posture_library: [坐, 躺, 指, 举]      # 可复现动作库
expression: 默认表情基调
forbidden: ["瘦长尖脸", "写实照片感"]
references: [character-ref-01.png]
```
> 铁律：角色**比例与识别点固定**，仅姿态/场景可变。否则不成 IP。

### 2 · 固定符号母题（sigil.md）
```yaml
id: sigil
name: 符号名
summary: 它在你体系里代表什么
form: 几何/手绘描述（如"缺口圆环内嵌一笔竖"）
grid: 16px 基准网格           # 符号构建网格，保证多尺寸一致
min_size: 24px                # 小于此不可识别，禁用
placement: [页角, 章节分隔, 水印]   # 固定出场位（强化记忆）
color: 引用 palette 签名色
forbidden: ["与角色抢视觉权重", "每版换形状"]
references: [sigil-ref-01.png]
```
> 铁律：符号**形状与出场位固定**，是"视觉指纹"。

### 3 · 专属配色签名（palette.md）
```yaml
id: palette
name: 签名色板
summary: 只属于你的配色，色即识别
signature:                   # 必含，全作品唯一锚点色
  hex: "#xxxxxx"
  role: 主识别色（出现即"这是你的"）
base: [底色, 字色, 分隔色]    # 中性基底
accents: [强调1, 强调2]       # 辅助
rule: "signature 色每作品必出现 ≥1 次；总色 ≤5"
forbidden: ["AI 紫 #xxxxxx", "荧光渐变"]
references: [palette-ref-01.png]
```
> 铁律：signature 色**跨作品恒定**，是识别核心。

### 4 · 字体人格（typeface.md）
```yaml
id: typeface
name: 字体人格
summary: 文字带脸的方式
display: 展示字体（如手写签名体名）
body: 正文字体
weight_rule: "标题永远 X 字重，正文 Y 字重"
signature_glyph: 你专属的某字写法（如"的"字特定笔顺/某标点造型）
forbidden: ["默认系统黑体", "衬线文艺腔"]
references: [typeface-ref-01.png]
```
> 铁律：展示字体**固定**，是文字层面的脸。

### 5 · 图形语言（graphic-language.md）
```yaml
id: graphic-language
name: 造型语法
summary: 统一造型基调
form_vocab: [圆润, 微手绘抖动, 粗描边]   # 全作品统一造型词
stroke: 描边粗细与端点（如"3px 圆头")
corner: 圆角/尖角尺度
texture: 统一质感（如"纸感颗粒"）
forbidden: ["直角硬边突然混入", "3D 写实"]
references: [graphic-language-ref-01.png]
```
> 铁律：造型语法**全作品一致**，是"手感"层面的识别。

## 三、容器目录约定

```
design-ip-assets/
  SKILL.md              # 本文件（含 5 类 schema + 对接规则 + 双路径）
  assets/               # 资产容器（每类一个 .md + 可选参考图）
    _README.md          # 如何新增/维护资产
    character.md
    sigil.md
    palette.md
    typeface.md
    graphic-language.md
  photos/               # 路径B 参考照（用户上传，仅提取锚点用，不进交付）
  contracts/            # 路径B 契约文件
    input-brief.yaml    # 授权/素材权利/任务简报
    character-spec-v1.yaml  # 冻结的角色卡（identity_lock/visual_lock/...）
    delivery-manifest.json  # 资产清单（路径B 扩展后登记）
```

**规则：**
* 资产**默认固定**，不随单次 brief 漂移；taste 可调，资产不动。
* 新增/修改资产 = 编辑 `assets/` 下对应 `.md`，不动本文件协议。
* 生成时**必须读 `references` 实际图**（若有），对齐资产视觉。

> **两条 IP 生成路径（二选一或并存）：**
> * **路径 A · 原创固定资产**（默认）：角色已固化为 `assets/*.md`，每次直接读资产绘制。见第四节~第六节。
> * **路径 B · 照片驱动生成**（新增）：用户提供 1–3 张参考照 → 提取人物锚点 → 生成可复用卡通 IP 原型 → 再扩展表情/动作包。见第七节~第八节。
> 两条路径共用同一套「五位一体资产 + 冻结扩展纪律」，只是角色来源不同（路径 A 来自资产文件，路径 B 来自参考照 + 冻结的角色卡）。

## 四、接入五层 / 模式 2 的约束权重

被「模式 2 ｜ 吸睛」或任何要品牌识别的设计调用时，本容器作为**最高优先级硬约束**（高于 taste）：

* **第一层 场景**：brief 涉及"品牌/系列/持续识别" → 强制激活本容器，资产不可省。
* **第二层 感知物料**：颜色取 `palette.md` 签名色；字体取 `typeface.md`；图片/纹理服从 `graphic-language.md`。
* **第三层 形式组织**：符号母题按 `sigil.md` placement 固定出场；角色按 `character.md` 比例/识别点。
* **第四层 信息叙事**：signature 色与角色作为记忆锚点贯穿。
* **第五层 主观输出**：验收含"是否一眼认出是你的"这一条。

**优先级裁决**：当 taste 实例的某维度与 ip-assets 冲突（如 taste 想要冷调但你的 signature 是暖橙），**以 ip-assets 为准**——品牌资产不可为单次调性让步。

## 五、资产落地检查（终检清单）

- [ ] **角色固定：** 本次角色比例/识别点与 `character.md` 一致，仅姿态/场景变？
- [ ] **符号固定：** 符号形状与出场位与 `sigil.md` 一致，未每版重画？
- [ ] **签名色在场：** `palette.md` 的 signature 色在本作品出现 ≥1 次？
- [ ] **字体固定：** 展示字体与 `typeface.md` 一致，未滑回系统默认？
- [ ] **图形语言一致：** 描边/圆角/质感全作品统一，无突兀混入？
- [ ] **优先级正确：** 与 taste 冲突时以 ip-assets 为准，品牌资产未被让步？
- [ ] **可识别验收：** 遮掉文字，能否凭角色/符号/色认出"这是你的"？

## 六、IP × 五层设计执行 SOP（每次设计照做）

> 第四节是"约束权重"，本节是"操作步骤"。拿到任意一次要带品牌识别的设计 brief，按下面 5 步走，**先读资产再动手**，禁止盲画（盲画 = 不看 `assets/*.md` 直接生成，结果必然贴皮不像）。

### Step 0 · 读资产（强制，不可跳过）
生成前必须 `read` 这五个文件，取到真实"脸"再动：
```
assets/character.md      # 角色比例 / 识别点 / 姿态库
assets/palette.md        # signature 色 + 基底 + 强调，记下 hex
assets/sigil.md          # 符号形状 + 固定出场位
assets/typeface.md       # 展示字体 + 正文字体 + 字重规则
assets/graphic-language.md # 造型语法（圆角/描边/质感）
```
> 若资产图（`*-ref-*.png`）存在，必须同时看，对齐视觉而非凭文字想象。

### Step 1 · 场景锚定（对应五层·第一层）
- 判定本次是否属于"品牌/系列/持续识别" → 是则本容器强制激活，资产不可省。
- 选本次 **taste 调性**（从 `design-taste/taste-profiles/` 挑），但记住：**taste 可调，资产不动**。

### Step 2 · 物料对齐（对应五层·第二层）
- 颜色：全部从 `palette.md` 取，signature 色必出现 ≥1 次，总色 ≤5。**禁 AI 紫 / 荧光 / 冷蓝主调**（具体占比规则见 `palette.md` 的 `rule`）。
- 字体：展示用 `typeface.md` 指定字体（无则找最近匹配，禁系统默认黑体作展示）；正文用指定黑体。
- 质感/描边/圆角：服从 `graphic-language.md` 的统一造型语法。

### Step 3 · 形式组织（对应五层·第三层）
- **角色**：按 `character.md` 固定比例与识别点绘制；仅姿态/场景可变（用 `posture_library`）。识别点缺一不可（见 `character.md` 的 `key_features`）。
- **符号**：按 `sigil.md` placement 出场（页角水印/章节分隔），**永远小且弱，不与角色抢权重**。
- 构图建议：角色做视觉主角，文案与角色共生（文案围绕/依偎角色），而非角色当装饰贴图。

### Step 4 · 叙事贯穿（对应五层·第四层）
- signature 色与角色作为记忆锚点贯穿全篇（刊头、主视觉、CTA、页脚都呼应）。
- 信息层级：角色情绪 → 主文案 → 行动点，顺序不散。

### Step 5 · 终检（对应五层·第五层 + 第五节清单）
跑第五节 7 条清单，全绿才算"这是你的"作品；任一不过 → 回到对应 Step 修正。

### 生成路线选择（按环境能力）
- **代码生成（SVG/CSS/Pillow）**：可控构图/网格/字重，但角色是几何近似、非手绘。适合做版式/海报骨架验证。
- **生图模型（即梦/可灵/SD）**：写带 IP 约束的 prompt（附 character/palette/sigil 硬约束），出真手绘质感。prompt 模板见下方。
- **优先级**：taste 与 ip-assets 冲突时以 ip-assets 为准。

### 附：生图模型 prompt 模板（路线 B，全流程引用资产文件，不内嵌具体 IP）
```
你是 <IP名> 的设计师。本次 brief：<填主题/载体>。
必须遵守的硬资产（不可偏离，全部取自 assets/ 下对应文件，不凭空编）：
- 角色：见 character.md（固定比例与识别点，仅姿态/场景可变）。
- 签名色：见 palette.md（signature 色必出现 ≥1 次，总色 ≤5，具体占比见其 rule 字段；禁 AI 紫/荧光/冷蓝主调）。
- 符号：见 sigil.md（按 placement 固定出场，永远小且弱）。
- 造型：见 graphic-language.md（统一造型语法）。
- 调性：<从 taste-profiles 选，如治愈/杂志感>，但资产优先级高于调性。
输出：<海报/头像/表情包 等>。
```

## 七、照片驱动路径（路径 B · 从参考照生成 IP）

> 当用户**没有现成固定角色**、但提供 1–3 张参考照（真人 / 手绘草稿 / 已有形象）想要做成可复用卡通 IP 时走此路径。目标是先"提取锚点 → 冻结原型"，再像路径 A 一样稳定扩展。

### 阶段零 · 授权与素材权利（前置，不可跳过）
- 接收照片前须取得用户**肖像/形象授权确认**（`likeness_consent`）；未确认不生成。
- 参考照仅用于**提取人物锚点**（脸型/发型/发色/标志性穿搭/气质），**不复制真人照片纹理、不做写实还原**；产出为卡通化/风格化 IP，非换脸。
- 原始照片**不复制进最终交付包**；只交付生成的卡通资产。

### 阶段一 · 风格与能力路由
- 先定本次 IP 风格（`style-id`）：可复用路径 A 的图形语言（`graphic-language.md`），或临时选一种卡通风格（简笔涂鸦 / 清透扁平 / 粉蜡笔 / 彩铅 / 手帐 / 粗线漫画等）。
- 声明**能力边界**（避免盲目承诺）：
  - `supported_forms`：本次直接可交付的（如 头像 / 半身表情贴纸 / 全身立绘 / 换装）。
  - `unsupported_forms`：明确不做的（如复杂场景、写实换脸），直接拒绝或推荐替代。
- 第一版**只用一个主风格**；融合风格须明确主辅，不平均混合。

### 阶段二 · 人物锚点提取（写进角色卡）
从参考照提取并冻结为角色卡字段（即本路径的"资产"）：
```yaml
identity_lock:    # 锁定，不可在扩展时改动
  face_shape: 脸型
  hair: 发型/发色/分缝
  glasses: 眼镜(有无)
  signature_wear: 标志性穿搭
  vibe: 气质基调
visual_lock:      # 造型锁（头身比/五官简化/线条/色块/材质/背景语言）
do_not_change:    # 明确禁止改的项
mutable_fields:   # 仅这些可在扩展时变：expression / pose / gesture / required_prop
generation_baseline: 风格渲染基线
```
- 只用一个**主身份图**定义锚点；辅助图仅用于校正某单项特征（冲突以主图为准）。
- 禁传边界：身份图不传皮肤纹理/真实鼻唇结构/单根发丝/摄影光影；保留"卡通化"距离。

### 阶段三 · 建立并冻结原型
- 按角色卡 + 风格生成 `prototype-v1-r1.png`，跑 QA（缩略仍可辨、无文字/水印、比例合风格）。
- 用户确认后**冻结为 `character-spec-v1`**，锚点图 `approved_anchor` 成为后续所有资产的**唯一人物锚点**。
- 此后扩展**禁止回头用真人照重新设计角色**，只以锚点延展。

### 阶段四 · 独立资产生产（表情/动作/贴纸包）
- 基于已冻结 `v1` + `approved_anchor` 扩展；先确认本轮资产清单。
- 每个表情/动作/换装/场景生成**一张独立 PNG**，只改 `mutable_fields`，其余继承锚点。
- 失败资产最多两次针对性重做（只改失败字段），仍失败则停止说明，不整包重生成。
- 透明贴纸需真实透明背景；所有独立资产 QA 通过后生成 `preview_sheet` 拼图（仅供预览，非源文件）。

## 八、IP 资产冻结与扩展纪律（两条路径共用）

> 路径 A（固定资产）与路径 B（照片驱动）都遵守同一套"不跑偏"铁律。核心：**角色一旦确认即冻结为锚点，扩展只动可变项，识别点锁死。**

### 版本铁律（dN / vN / rN）
- `dN`：草案（未确认，只生成原型候选）。
- `vN`：确认身份版本（用户明确确认后冻结，锚点锁定）。
- `rN`：发布资产（表情/动作/贴纸等扩展，基于 vN）。
- 改**识别点/锁定项**必须建 `dN+1` → 确认冻 `vN+1`，**不得直接覆盖旧版**；新表情/资产建 `rN+1`。回退切旧版不混用。

### 锁字段保护
- `identity_lock` / `visual_lock` / `do_not_change` 为**不可变锁**；用户要求改这些 → 先建草案版本，不直接改 prompt 覆盖。
- 每轮只改点名的 `mutable_fields`（表情/姿势/手势/必要道具），其余继承锚点。

### 五段式生图提示词模板（替换上方松散模板，两条路径通用）
按顺序填入，方括号内容必须来自角色卡/资产文件/风格 spec，**不虚构**：
```
[1 输入图职责] 身份参考（路径A=assets图；路径B=approved_anchor）与风格参考的命名职责及冲突优先级。
[2 不可变的人物锁] 严格保持 vN 的 identity_lock / visual_lock / do_not_change；不留真人照片纹理/结构/光影。
```
