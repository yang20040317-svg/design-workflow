# 第3层·形式组织 / 子位置：关系

> 本子位置是独立可编辑模块，可单独编写，不依赖其他子位置文件。

## 本子位置定位
- 层：第 3 层 · 形式组织
- 子位置：关系
- 一句话说明：元素之间的视觉关联——对比 / 重复 / 对齐 / 亲密性 / 图底 / 平衡 / 节奏（CRAP 原则）
- **心智模型**：关系 = 元素之间的对话。单个元素再好看，关系乱了整体就散；关系对了，观者才能顺畅读懂并「相信」这个设计。第 2 层产出了材料，本子位置决定这些材料彼此如何对话、谁主谁次。

## 在工作流中的位置（默认顺序 · 可跳层回补）
- 上一步输入：第 1 层场景（布局约束）、第 2 层各物料（文字 / 颜色 / 图片 / 动画 / 纹理 / 模型已定）
- 本步要做：建立元素间视觉关系——谁和谁一组、谁强谁弱、靠什么对齐、图底谁主谁次；产出「关系规格」（分组 / 层级 / 对齐网格 / 图底 / 平衡）
- 输出给：本层后续子位置「排版构图」「镜头布局」；第 4 层「信息叙事」（关系服务于信息主次）

## 操作要点

### 1. 关系家族分类（元素间靠什么产生联系）
| 关系类型 | 作用 | 表现 |
|---|---|---|
| 对比 Contrast | 制造焦点、区分主次 | 大小 / 明暗 / 色彩 / 粗细反差 |
| 重复 Repetition | 统一、节奏、品牌感 | 同形状 / 同色 / 同间距反复 |
| 对齐 Alignment | 秩序、整洁、专业 | 共基线 / 共轴线 / 网格 |
| 亲密性 Proximity | 归类、降低认知负担 | 相关元素间距更近 |
| 图底关系 Figure-Ground | 谁主谁次、可读性 | 主体从背景中「跳」出 |
| 视觉平衡 Balance | 稳定感 / 动感 | 对称 / 非对称 / 三分 |
| 节奏韵律 Rhythm | 引导视线流动 | 元素大小 / 位置渐变 |
| 统一与变化 Unity/Variety | 整体不单调 | 统一基调 + 局部变化 |

### 2. 四步定位法（建立关系）
1. **识别元素组**：哪些信息是一伙的（标题 + 副标题、时间 + 地点、标签 + 数据）。
2. **定关系类型**：每组用什么关系组织（亲密性归类、对比拉主次、重复做节奏）。
3. **排关系强度**：对比强不强、间距疏不疏——强度决定关系「被读出来」的明显程度。
4. **查整体平衡**：所有关系加起来，画面是稳的、还是散的、乱的。

### 3. 维度五件套（描述一套关系的五个角度）
- **关联方式**：对比 / 重复 / 对齐 / 亲密 / 图底，选哪些、怎么组合
- **视觉权重**：谁重谁轻，主信息权重最高
- **间距与亲密性**：相关近、无关远（亲密性）
- **对齐基准**：共基线 / 网格 / 轴线
- **图底清晰度**：主体能否从背景清晰跳出

### 4. 关键方法
- **CRAP 四原则（设计基本功）**：
  - 对比：不想一样就让它明显不同——避免「差不多」，差不多 = 混乱
  - 重复：视觉要素（颜色 / 形状 / 间距）反复出现，建立统一与节奏
  - 对齐：任何元素都不随意摆放，找一条隐形基线 / 轴线对齐
  - 亲密性：相关信息靠在一起，无关信息拉开
- **图底关系（figure-ground）**：确保主体从背景清晰分离（用对比 / 留白 / 框）；图底暧昧 = 看不懂主次，这是可读性根基。
- **视觉平衡**：对称 = 稳重正式；非对称（三分法 / 对角线）= 活泼动感。重量来自大小 / 颜色 / 密度——小块亮色能压过大块灰。
- **主次权重**：用关系把「主信息」权重顶到最高（对比最强 / 位置最显 / 面积最大），其余递减，服务第 4 层信息优先级。
- **节奏与重复**：重复形状 / 间距制造韵律，引导视线沿设计走；重复也是品牌识别手段。
- **留白也是关系**：元素间的空白定义了它们的关系（亲密 or 疏离），别填满——负空间是最高级的关系调控。

### 5. 上下层与同层衔接
- **← 第 2 层**：物料已定（字重对比、颜色主辅、图片主体），本层用关系把它们组织起来。
- **→ 第 3 层**：关系规格喂给「排版构图」（具体位置 / 网格落地）、「镜头布局」（景深 / 主次机位）；关系是构图骨架。
- **→ 第 4 层**：关系是信息主次的视觉化身——第 4 层定「说什么先说」，本层用对比 / 权重让「先说」被看见。

## 补充 · 扁平 grid vs wrapper 容器（关系密度的两极）

> 当一组元素彼此**无主次、并列存在**时（4 个产品系列、同级条目、并列档位），选扁平 grid 直接铺；只有当元素**从属于一个父概念 / 必须显式归一组**时，才加 wrapper 容器。

### 判据三问（要素并列关系判定）

- **是否真有一组都从属于"父概念"？** 是 → 可加 wrapper（如"三条信号 ← 背景"）；否 → 不加（如四个独立产品系列不"从属于"任何概念）。
- **会否让每张卡显得"被框住 / 集装箱"？** 外层容器 `+ grid gap:1px + 卡片背景板` 三件套叠起来时，视觉上每个 card 像被"装进一个盒子"，整体就散了——这是把 4 列扁平 grid 写成 `display:grid + 4 cards` 时最常踩的坑。
- **是否真的需要"分组归属"的视觉提示？** 用户能否一眼看出 4 张卡是"同一类"？多数情况下靠 card 自身排版（统一字号、统一顶边细线、共享配色）就能传达，无需 wrapper。

### 什么时候选扁平 grid（v1 默认做法）
- **同级并列元素**：4 个产品系列 / 6 条用户特征 / 3 种竞品关键词——彼此**没有从属关系**，直接以 `repeat(N, 1fr)` 铺。
- **每元素自承载**：每张 card 内部已有完整表达（标题 + 描述 + 规格 + 视觉锚点图），不需要 wrapper 再加一行"分组标签"。
- **强视觉锚点**：每张 card 配内联 SVG / 图标作视觉锚点，避免纯文字卡的空洞。

### 什么时候选 wrapper 容器（必要场景）
- **真分组归属**：一组卡片"从属"于一个独立的小节（如背景页三条"信号 A/B/C"），用 wrapper 把它们打成"信号"这一组。
- **小节标题承载**：wrapper 容器内部有"小节标题"，容器本身就是小节的可视化。
- **共享大背景板**：所有 card 都**形式上**共享同一色块（如深色卡片群 / 同色质感组），这是用容器的合理场景。

### 实现要点（v1 4 列扁平写法参考）
```css
/* v1 4 列扁平案例 grid：直接 grid，不加外层 .series 容器 */
.case-grid{display:grid;grid-template-columns:repeat(4,1fr);gap:24px;margin-top:2.2rem}
.case-card{background:transparent;padding:1.2rem .4rem .8rem;border-top:1px solid var(--line);transition:transform .5s var(--ease)}
.case-card:hover{transform:translateY(-6px)}
.case-card .bottle-art{height:84px;display:flex;align-items:center;justify-content:center;margin-bottom:1rem}
.case-card .case-spec{display:flex;justify-content:space-between;font-size:.58rem;letter-spacing:.18em;border-top:1px dashed var(--line);padding-top:.7rem}
```
要点：
- card 用 `background:transparent`（不要米色背景板）——让卡片在主背景上"呼吸"
- 仅保留 `border-top:1px solid var(--line)`，不要围合边框；多个卡靠"底边 + 顶细线"形成横向延续感
- 每张卡配内联 `.bottle-art` SVG 作视觉锚点（不可省）
- hover 时 `transform:translateY(-6px)` 给微抬反馈
- 媒体查询：≤980px 改 2 列、≤640px 改单列

## 备注
- 关系是「组织逻辑」，排版构图是「落位执行」：本层定「谁和谁一组、谁主谁次」，「排版构图」定「具体放哪、多大」。
- 与第 4 层信息叙事强耦合：信息优先级 → 关系权重，一一对应。
