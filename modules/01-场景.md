# 第1层·场景（合并模块：载体 · 环境 · 上下文 · 客观约束）

> 所属工作流步骤：第 1 步（顺序：第一层 → 第二层 → 第三层 → 第四层 → 第五层）
> 本文件把场景层的 4 个子位置合并为一个可编辑模块，每节独立，可单独编写维护。

## 本模块定位
- 层：第 1 层 · 场景
- 一句话说明：先定前提与边界——在哪里（载体）、什么情境（环境）、什么背景（上下文）、什么红线（客观约束）
- 内部顺序：载体 → 环境 → 上下文 → 客观约束（依次推进，做完再进第 2 层）

---

## ⚠️ 进场闸门：场景不清，绝不动手

本层是整个工作流的地基。**在场景（载体 / 环境 / 上下文 / 客观约束）没有完全搞清楚之前，禁止进入第 2 层，也禁止做任何视觉产出（不动手）。** 哪怕只是「大概」「应该」「先默认一下」也不行——**不清楚就问用户，拿到明确答复再推进**。

- **必须向用户确认清楚的四件事**：
  1. **载体**：作品最终在什么上面展示？（不明确就问，绝不默认）
  2. **环境**：在什么物理 / 屏幕情境下被看？（光线 / 距离 / 移动 / 公众性）
  3. **上下文**：给谁看、什么目的、什么调性、有无时间 / 事件背景？
  4. **客观约束**：是否商用？（商用才触发严格红线；否则轻量）有无版权 / 平台 / 预算硬限制？
- **判断红线**：以上任一项你只能「猜」而不能「确认」，就**停下来问用户**，不要凭假设继续往下走。
- **为什么这么硬**：场景层错一层，后面四层全白做。多问一句的成本 << 地基返工的成本。
- **怎么问**：用具体问题把模糊处逼出来。例如：「这张图主要投哪个平台？主载体是什么？」「是自用还是商用？」「给谁看、想要什么感觉？」拿到答复再开工。

# 小节 1 ｜ 载体

## 载体是什么（先对齐概念）

**载体（carrier）= 你的设计作品最终被承载、存放、展示在什么东西上面。**
它是容器 / 介质，用来「托住」全部视觉内容（文字、图片、构图）。**载体的边界就是设计的边界**——内容画不出载体，也逃不出载体。

常见例子：

| 作品 | 载体 |
| --- | --- |
| 打印一张海报贴墙上 | 那张纸质海报（纸张） |
| 小红书封面图 | 小红书图片画布（1080×1440，平台会裁剪，jpg，手机屏幕展示） |
| PPT 一页幻灯片 | 这一页幻灯片画布 |
| 网页页面 | 浏览器视口 / 网页画布 |
| 广告牌 | 广告牌实体板面 |
| 3D 虚拟空间里一块悬浮 UI 面板 | 这块虚拟面板 |

## 载体家族（按介质分类，设计时先从这张表里定位）

- **印刷类**：海报 / 纸张、书籍杂志页、包装、名片卡片、DM 折页、易拉宝、灯箱
- **屏幕数字类**：手机竖屏画布（小红书 / 朋友圈 / 抖音）、网页视口、PPT 幻灯片、桌面窗口、平板、电视 / 户外大屏、车机屏幕、手表屏幕
- **空间实体类**：广告牌板面、空间导视、展陈墙面、橱窗、横幅
- **产品实体类**：包装盒体、产品外壳丝印、标签贴纸、杯子 T 恤等周边
- **3D / 虚拟类**：3D 虚拟空间悬浮 UI 面板、AR 覆盖层、游戏 HUD、VR 界面、空间计算界面
- **时间动态类**：视频 / 动画画布、可交互页面、动效界面（载体不只是静态平面，也可能是有时间轴与交互的）

## 在工作流中的位置（顺序执行）
- 上一步输入：需求 / 目标（流程起点，由需求直接触发；需求里通常已经隐含了载体，例如「做一张小红书封面」）
- 本步要做：把需求落到**具体的载体对象**上，并查出它的一整套硬参数（见「载体参数五件套」），把边界钉死
- 输出给：同模块后续小节（环境 / 上下文 / 客观约束）及第 2 层（载体规格卡喂给字号与图片规格）

## 操作要点

### 1. 具体怎么操作（四步定位法）
1. **落到对象**：问「作品最终在什么上面展示？」，从载体家族表里点出一个具体载体（不是「做个设计」，而是「印在 A3 纸上」/「发在小红书」/「挂在 3D 场景里」）。
2. **查出规格**：查该载体的官方 / 行业规格——平台画布尺寸、印刷成品尺寸与出血、屏幕分辨率档位、空间面板的物理尺寸与像素密度。
3. **钉死边界**：把载体的尺寸、安全区、格式、色彩空间写成一行「载体规格卡」，作为本层产出。
4. **多载体反查**：一个设计可能出现在多个载体上（如主视觉同时用于海报 + 朋友圈 + 网页）。此时**确定主载体**（以它定稿），其余作为适配载体（只做规格适配，不重画）。

### 2. 载体参数五件套（每种载体必须确认）
1. **尺寸**：宽 × 高。含印刷出血、平台安全边距、网页响应式断点、虚拟面板的 world-space 尺寸。
2. **分辨率 / 密度**：印刷 300dpi、屏幕 1x / 2x / 3x（如 iOS @2x @3x）、大屏按 PPI 反推。
3. **格式与色彩**：文件格式（jpg / png / pdf / svg / mp4 / glb）、色彩空间（印刷 CMYK、屏幕 RGB、广色域 P3）、透明通道是否可用。
4. **观看距离与视场**：广告牌远看（字号下限要高）、手机近看（字号可以小）、3D 面板可走进看也可拉远看（要考虑最小可读尺度）。
5. **交互与动态能力**：静态不可点 / 可滚动 / 可点击 / 有动效 / 有时间轴。决定内容能否分层、能否用微交互。

### 3. 关键方法与注意
- **载体先于内容**：先定载体，再谈颜色、字体、排版。载体错了，后面全是白做。
- **平台裁剪意识**：小红书封面 1080×1440 但列表会裁、朋友圈 1:1 居中裁、抖音 1080×1920 有底部遮挡。核心内容必须放进**安全区**。
- **印刷三件事**：出血（一般 3mm）、CMYK 色彩模式、嵌入字体或转曲。
- **格式即能力**：jpg 无透明通道、png 有、svg 无限放大、mp4 才有动画——载体限定了格式，格式限定了能做的手法。
- **虚拟面板特例**：3D / AR 载体还要额外确认**可接近距离、朝向、是否常驻视口**，并且常受引擎或平台（WebGL / 游戏引擎）的渲染规格约束。

### 4. 与其他小节 / 层的衔接
- 同模块内：载体 →「环境」（观看光线 / 移动 / 公众性）→「客观约束」（平台规则、预算工期）→「上下文」（业务与文化背景）。
- 下一层：载体规格卡直接喂给第 2 层感知物料——字号下限、图片尺寸、色板空间都以它为基准。

### 4.5 多尺寸画板库（同一内容跨平台适配）
> 同一设计常要发多个平台，平台画板比例不同。

- 常用画板比例：3:4 竖版（小红书/公众号封面）、1:1 方版（朋友圈/头像）、21:9 宽版（横幅/封面条）、16:9（视频封面/网页）、9:16（短视频/故事）。
- **适配原则**：确定**主载体**（以其定稿），其余平台只做**比例 + 裁切 + 安全区**适配，不重画结构；核心内容放进所有平台的安全区。
- 与「平台裁剪意识」呼应：主视觉构图要能在各比例下都成立（用安全区兜底）。

### 4.6 交付形态（设计产物判定 · 本技能只做设计）

> **为什么有这一节**：同一载体可以有不同交付形态。本技能交付的是**设计物**——设计稿 / 可交互原型，**不是可安装运行的应用程序**。动手前先判定交付形态，第 5 层的验收标准和交付物格式从一开始就钉死，避免"做完了才发现形态不对"。

**边界红线（本技能只做设计）**：
- ✅ 交付形态：静态图 / 海报、网页界面稿、移动端界面稿、叙事长页、视频 / 动效分镜、品牌视觉规范——一切**设计产物**。
- ❌ 不交付：可安装运行的应用（Expo / React Native / 原生 App）、带后端 / 数据库的可部署系统。那是**工程线**（ae-factory）的职责，不在本技能内做工程化。

**判定四步**：
1. **问形态**：「这次交付的是哪种设计形态？」从下表点一个；用户只说"做个应用 / 做个 App"时，先判他指的是**界面设计稿**（本技能做）还是**可运行应用**（工程线做），不默认成工程任务。
2. **落格式**：静态图（jpg / png / svg / pdf）？界面稿（高保真稿 / 可交互原型）？动效（mp4 / 分镜）？
3. **钉验收**：第 5 层验收以该形态的完成度为准（海报看静态完成度；界面稿看结构 / 层级 / 交互意图；动效看首帧 + 节奏）。
4. **防串味**：若用户最终要"真应用"，本技能交付设计稿后**交给工程线承接**，不在本技能内做工程化——设计归设计，工程归工程。

| 交付形态 | 是什么 | 验收标准（第 5 层） |
| --- | --- | --- |
| 静态图 / 海报 | 单张或多张平面图 | 静态完成度 + C 段三动作（硬闸门） |
| 网页界面稿 | 网页 UI 设计（高保真稿 / 可交互原型） | 结构 / 层级 / 交互意图成立 |
| 移动端界面稿 | 手机 App 界面设计（高保真稿 / 可交互原型） | 移动结构约束 + 交互意图成立 |
| 叙事长页 / 信息页 | 长滚动页面 / 报告页 | 隐喻统一 + 节奏成立 |
| 视频 / 动效分镜 | 动态视觉脚本 / 动画 | 首帧静态合格 + 节奏成立 |

### 5. 领域适配：载体决定下游子位置用 / 跳过（软门控）

> 第 1 层定下的**载体**，天然决定第 2–5 层哪些子位置要走到、哪些可跳过。这是**软门控**（核心 / 条件适用 / 跳过），不是硬禁止——「跳过」指该载体默认不涉及，「条件适用」指遇到才走，「核心」指必走。出现特例（如 3D 渲染海报、合成 3D 元素的图片）按实情放行，不让表格反向约束创意。
> 用法：载体定下后，顺着五层往下走时，对每层子位置先查下表，跳过标「跳过」的、按需走「条件适用」的。

| 载体（第 1 层定） | 第2层 感知物料 | 第3层 形式组织 | 第4层 信息叙事 | 第5层 主观输出 |
| --- | --- | --- | --- | --- |
| **图片海报 / 静态平面**（印刷海报、小红书封面、朋友圈图、易拉宝） | 文字·颜色·图片·纹理·空间·关系·排版构图 = 核心；动画 = 跳过；模型 = 跳过（除非合成 3D 元素 / 本身是 3D 渲染产物） | 空间·关系·排版构图 = 核心；镜头布局 = 条件适用（摄影构图参考，非必走） | 信息优先级·故事逻辑·表达意图 = 核心 | 感觉·情绪·心理体验 = 核心 |
| **视频 / 动效 / 短视频** | 文字·颜色·图片·纹理·空间·关系·排版构图 = 核心；模型 = 条件适用（含 3D 元素时）；动画 = 条件适用（时间轴手法） | 空间·关系·排版构图 = 核心；镜头布局 = 核心（运镜 / 景别 / 景深必走） | 全部核心（故事逻辑 = 分镜顺序） | 全部核心 |
| **3D / 虚拟空间 / 产品渲染**（3D 面板、AR、游戏 HUD、产品渲染图） | 模型 = 核心；颜色·纹理（3D PBR 材质）·空间 = 核心；文字·图片 = 条件适用（UI overlay / 贴图）；动画 = 条件适用 | 镜头布局·空间·关系 = 核心；排版构图 = 条件适用（含文字时） | 全部核心 | 全部核心 |
| **UI / 数字产品 / 网页** | 颜色·文字·纹理·空间·关系·排版构图 = 核心；图片 = 条件适用（配图 / icon）；动画 = 条件适用（微交互）；模型 = 跳过（除非 3D 产品展示） | 空间·关系·排版构图（界面布局 / 栅格）= 核心；镜头布局 = 跳过（无摄影镜头概念，改用响应式断点 / 视口） | 全部核心 | 全部核心 |
| **印刷**（书籍页 / 包装 / 名片 / 折页 / 灯箱） | 文字·颜色·图片·纹理（专色 / 烫印 / 压凹工艺）·空间·关系·排版构图 = 核心；动画 = 跳过；模型 = 跳过 | 空间·关系·排版构图 = 核心；镜头布局 = 跳过 | 全部核心 | 全部核心 |

**软门控原则（务必遵守，避免表格反向约束创意）**：
- 「跳过」≠ 永远禁用：它说的是「该载体默认不涉及此子位置」；一旦特例出现（图片海报用了 3D 渲染产物 / 合成 3D 元素、UI 里用 3D 产品展示），对应子位置转为「条件适用」，按实情走。
- 「条件适用」= 视具体任务而定，遇到才走，不必每单都做。
- 本表是载体维度的**默认路由**，不是新规则；真正的内容与方法仍由各子位置文件（`modules/02`–`05`）负责。

**内容形态的二次路由（防漏兜底）**：载体门控只管介质，管不了内容形态。若第 1 层识别到内容是**"一段经历 / 一串时间节点 / 一份履历 / 一个产品故事"**——典型为作品集、个人主页、简历页、时间轴长页、年报、里程碑页——除按上表走五层外，**另路由 `subskills/design-metaphor-narrative`**（隐喻统摄 / 门禁序章 / 字段实物替身 / reveal 错峰等），不要等走到第 4 层才想起来。

### 5.5 领域适配（语义门控）：领域 × 载体 的第二个维度

> **为什么需要这一节**：上一节「载体门控」只回答「作品落在什么介质上」（纸 / 屏 / 3D / 网页），它决定图层走哪些子位置。但**同一载体可以承载完全不同的领域**——一个 UI 可以是冥想 App、也可以是银行 App、也可以是外卖 App；一张海报可以是品牌官宣、也可以是公益呼吁、也可以是促销。载体门控管不了「这个领域该有什么组件、这些组件怎么空间组织、信息怎么排优先级」。**这一节补上「领域」维度：领域决定语义组件与空间结构，载体决定介质参数。两者正交，都要门控。**

**关键原则（务必遵守）**：
- 领域适配**不是抄参考图的配色与装饰**，而是从**领域本身的真实功能/语义**长出组件与空间结构。参考图只用于验证「这个领域的真实产品长什么样」，不是直接搬运其视觉元素到不相关的领域。
- **反模式红线**：禁止把 A 领域的组件硬塞进 B 领域当装饰（如把金融 App 的「支出折线图」套到冥想灵感卡上充当装饰曲线——图有数据才有意义，无数据的曲线是假的领域不适配）。
- 领域语义门控的输出（组件清单 + 空间逻辑 + 信息优先级 + 反模式）**直接喂给第 3 层形式组织**（空间 / 关系 / 排版构图用领域组件当素材）与第 4 层信息叙事（优先级 / 故事逻辑按领域来），而非只喂第 2 层配色。

#### 领域适配表（按领域，跨载体通用）

> 每个领域给出四样东西：**真实组件**（从领域本身长出，不是抄来的）、**空间组织逻辑**（为什么这么排）、**信息优先级**（主/次/辅）、**反模式**（什么绝对不该出现）。载体参数仍查上一节「载体门控」表。

| 领域 | 真实组件（领域长出） | 空间组织逻辑 | 信息优先级 | 反模式（禁止） |
| --- | --- | --- | --- | --- |
| **灵感 / 冥想 / 慢生活** | 今日一句（大字留白）、灵感卡流（短语+署名）、呼吸/暂停引导、收藏夹、心情标记、期号/栏目分割 | 编辑式非对称：一句超大标题出血到边，大留白呼吸，卡片流靠留白分而非线切；强调元素极小面积 | 主=今日一句；次=灵感卡流；辅=栏目/期号 | 禁：金融式数据卡、无意义装饰曲线、密集网格、促销式强对比 |
| **金融 / 账务 / 交易** | 账户总览卡（余额/卡号）、交易流水、分类统计、预算进度、资产走势（**有真实数据的折线/柱状**） | 一主账户卡占顶 1/3，下方流水密铺；数据密度高但分区清晰 | 主=账户总览；次=近期交易；辅=统计/预算 | 禁：无数据装饰图、模糊文案、把数字当氛围元素 |
| **内容消费 / 信息流**（资讯/社区/短视频） | 信息流卡片、封面缩略、标签/话题、互动数据（赞/评/藏）、详情页、评论层 | 单列流或双列网格；封面驱动点击；详情页承接深度阅读 | 主=流内头条；次=相关推荐；辅=互动/评论 | 禁：把内容流做成工具式表单、过度装饰干扰阅读 |
| **工具 / 效率**（待办/笔记/日历） | 列表/分组、输入入口、状态标记（完成/进行）、筛选/搜索、日历网格 | 高密度、清晰分区、操作可达；留白服务于扫读而非氛围 | 主=当前任务/今日；次=待处理；辅=归档/设置 | 禁：氛围化大留白牺牲可用性、装饰压过功能 |
| **品牌 / 官宣 / 形象** | 主视觉、标语、品牌符号、关键信息块、行动召唤（CTA） | 强焦点单主体，视觉流向引导到 CTA；留白服务聚焦 | 主=品牌主张；次=支撑信息；辅=合规/署名 | 禁：信息过载、多主体争抢、无明确视觉落点 |
| **电商 / 商品** | 商品卡（图/价/标题）、购物车、详情、评价、利益点 | 商品图主导，价格/利益点紧邻；转化路径短 | 主=商品与价格；次=评价/详情；辅=推荐 | 禁：弱化价格、隐藏关键信息、氛围压过商品 |
| **教育 / 知识** | 知识点卡、进度、练习、讲解流、章节导航 | 循序渐进的线性/树状结构；进度可视 | 主=当前知识点；次=练习/测验；辅=拓展 | 禁：信息跳跃无结构、缺进度反馈 |
| **空间 / 展陈 / 导视** | 导视牌、信息柱、动线、点位标识、环境图形 | 按人体尺度与动线排布；远看可辨、近看有细节 | 主=当前位置/去向；次=周边信息；辅=品牌 | 禁：小字密排、无方向感、与环境光冲突 |
| **3D / 虚拟空间 / 模型** | 可交互模型、视角控制、材质/光照、信息 overlay、空间锚点 | 以世界尺度与可接近距离组织；overlay 不挡主体；光影即信息 | 主=模型本体；次=交互提示；辅=元数据 | 禁：overlay 过载、忽略最小可读尺度、材质无逻辑 |

#### 用法（落在五层里）
1. 第 1 层场景：先定**载体**（上一节门控表），再定**领域**（本节领域表）——两者都定，才算场景清晰。
2. 领域表的「真实组件」→ 作为第 3 层形式组织的**素材清单**（空间/关系/排版构图拿这些组件排，而不是拿通用占位排）。
3. 领域表的「空间组织逻辑」→ 直接约束第 3 层（如灵感领域用编辑式非对称，不是居中对称网格）。
4. 领域表的「信息优先级」→ 直接喂第 4 层信息叙事（主/次/辅权重按领域来）。
5. 领域表的「反模式」→ 第 2–5 层产出的**否决清单**（产出的东西踩了反模式就打回，不论配色多好看）。
6. **参考图的正确用法**：找参考图是为了确认「该领域的真实产品/作品长什么样、组件是否齐全」，不是把参考图的视觉元素搬运到当前领域。抄袭配色/装饰而不长组件，视为领域不适配。

> **动态素材首帧优先**：当载体含时间轴/动效（视频/动效/短视频/Live Photo）时，**动态素材的第一帧必须先像一张「合格的静态卡」**——画面文案描述真实场景/内容而非制作术语，首帧单独成立、不依赖播放才懂。过此关再出动态包（时长/平台发布路径按客观约束）。

# 小节 2 ｜ 环境

## 环境是什么（先对齐概念）

**环境（environment）= 作品被谁、在什么物理与社会情境下观看 / 使用。**
它决定「看不看得到、看不看得清、要不要细看」。同一张图，在强光户外大屏和深夜手机被窝里，有效信息量天差地别。**环境不是装饰，是硬约束**——它直接锁死对比度下限与信息密度上限。

四个维度（判断环境就问这四件事）：

| 维度 | 问自己 | 对设计的硬影响 |
| --- | --- | --- |
| 光线 | 亮还是暗？自然光还是屏光？ | 对比度下限、是否自发光、配色深浅 |
| 噪声 | 旁边有别的视觉 / 听觉干扰吗？ | 信息聚焦度、留白、动效克制 |
| 移动 | 观看者在走 / 坐 / 开车？ | 字号下限、一屏可读、避免精细操作 |
| 公众性 | 公共场合还是私密？ | 可读性距离、内容普适性、可否含个人信息 |

常见环境示例：

| 场景 | 环境特征 | 设计对策 |
| --- | --- | --- |
| 户外广告牌 / 灯箱 | 强光、远距离、移动观看 | 超大字、极高对比、信息极简 |
| 地铁 / 公交车厢 | 晃动、短暂停留、可能强光 | 一屏核心信息、抗抖可读性 |
| 手机朋友圈（躺看） | 弱光、近距离、静止 | 可含细节、深色底也行 |
| 车内中控屏 | 强光 + 移动 + 需秒懂 | 超大触控目标、禁细读 |
| 会议投屏 PPT | 中距离、静止、室内光 | 字号够远排、少字多图 |
| 电商详情页（沙发上） | 居家、静止、可滚动 | 可接受长图文 |

## 在工作流中的位置（顺序执行）
- 上一步输入：需求 / 目标 + 本模块小节 1「载体」（载体规格卡，已定尺寸与观看距离）
- 本步要做：判断作品在什么物理情境下被看——光线强弱 / 环境噪声 / 观看者是否移动 / 公共还是私密，并定出**对比度与信息密度要求**
- 输出给：本模块后续小节（客观约束、上下文）及第 2 层（对比度 / 字号下限 / 信息密度要求，直接喂给颜色与文字）

## 操作要点

### 1. 具体怎么操作（四步判断法）
1. **定光环境**：问「主要在哪里、什么光线下看？」——户外强光 / 室内恒光 / 暗场自发光。以**最差光环境**为准（户外就按正午直射算）。
2. **定动静**：观看者是在移动（地铁 / 走路 / 开车）还是静止？移动则字号与触控目标上调、信息一屏化。
3. **定公众性**：公共大屏（远距离、内容普适）还是私密手机（可含个人 / 精细信息）？
4. **钉死两条线**：写出「对比度下限（如正文 ≥ 4.5:1）」与「字号下限（如最小 14pt / 远看 ≥ 主视觉高度 1/10）」，作为本步产出。

### 2. 环境维度四件套（每个设计必须判断）
1. **光线**：强光 → 深字浅底、避免细描边与浅灰小字；暗场 → 可自发光、避免纯黑底配暗字（无层次）；混合光 → 按最差算。
2. **噪声**：视觉噪声高（旁边内容抢注意力）→ 更聚焦、更大留白；听觉噪声高（嘈杂）→ 不能依赖「听」，纯视觉传达；信息噪声高 → 克制动效。
3. **移动**：移动中看 → 字号下限提高、核心信息一屏可读、避免精细操作与长文。
4. **公众性**：公共场合 → 远距离可读、内容普适不过私；私密 → 可含个人信息、可精细。

### 3. 关键方法与注意
- **以最差环境为准**：别按「理想情况」设计。户外物料按正午强光算对比度，App 按阳光下可读算。
- **做极端环境预览**：把稿子放到最亮 / 最暗背景上、缩到最小尺寸看是否还认得出——这一招能拦掉大部分翻车。
- **环境决定信息密度上限**：越动、越亮、越远，信息越少。宁少勿挤。
- **与载体联动**：观看距离已在「载体」里定（广告牌远、手机近），这里把它翻译成具体的字号 / 对比度数字。

### 4. 与其他小节 / 层的衔接
- 同模块内：环境 →「客观约束」（公共场合还要叠加合规 / 平台红线）→「上下文」（人群审美）。
- 下一层：对比度与字号下限直接喂给第 2 层——颜色（深浅对比）、文字（字号层级下限）。

- [ ] 是否判断了观看者动静，并相应上调字号 / 一屏化？
- [ ] 是否判断了公众性，内容是否普适、有无私密泄露？
- [ ] 是否钉死了对比度下限与字号下限（写成了数字）？
- [ ] 是否做过极端环境预览（最亮 / 最暗 / 最小尺寸）？

# 小节 3 ｜ 上下文

## 上下文是什么（先对齐概念）

**上下文（context）= 作品所处的业务、人群、文化与时间背景。**
它决定「说什么、对谁说、什么能说、什么绝对不能说」。同样的红色，在年货节是喜庆，在哀悼专题是失礼——**语义是语境给的，不是颜色给的**。

五个背景维度：

| 维度 | 问自己 | 对设计的硬影响 |
| --- | --- | --- |
| 品牌调性 | 这个品牌是什么性格？ | 风格方向、字体语气、构图气质 |
| 目标人群 | 给谁看？什么审美习惯？ | 视觉语言、梗 / 梗体、信息深度 |
| 竞品惯例 | 同赛道都在怎么画？ | 跟趋势还是反套路 |
| 文化语境 | 什么地域 / 亚文化符号？ | 符号语义、禁忌雷区 |
| 时间节点 | 什么节日 / 热点 / 季节？ | 可借势、可避嫌 |

常见上下文示例：

| 场景 | 上下文特征 | 设计对策 |
| --- | --- | --- |
| 新年红包 / 拜年 | 红金、喜庆、团圆 | 暖色、传统纹样、圆润字形 |
| 科技发布会主视觉 | 极简、未来感、理性 | 深蓝黑、大留白、无衬线 |
| 公益活动 | 真实、温暖、共情 | 实拍影像、克制配色 |
| 双十一大促 | 疯抢、紧迫、利益点 | 强对比、利益字大、倒计时 |
| 品牌升级官宣 | 高级、克制、新身份 | 留白、细节、少字 |

## 在工作流中的位置（顺序执行）
- 上一步输入：需求 / 目标 + 本模块小节 1、2（载体规格卡、环境要求）
- 本步要做：梳理业务背景、面向人群、文化语境与时间节点，明确**语义基调**与**不可触碰的禁忌**
- 输出给：本模块后续小节（客观约束）及第 2 层（色板语义、字体语气受上下文约束）

## 操作要点

### 1. 具体怎么操作（四步梳理法）
1. **定品牌调性**：抽象出 2~3 个词（如「专业 / 温暖 / 年轻」），作为风格总纲。
2. **定目标人群**：画出人群画像与审美习惯（年轻人爱梗、商务爱克制），决定视觉语言的「语言」。
3. **查文化与竞品**：列出本文化 / 亚文化里的符号语义与雷区，以及竞品视觉惯例（跟 or 反）。
4. **定语义基调 + 禁忌清单**：写出「要传递的情绪 / 语义」与「绝对不能出现的符号 / 配色 / 用语」，作为本步产出。

### 2. 上下文维度五件套（每个设计必须梳理）
1. **品牌调性**：科技极简 vs 温暖手作 vs 奢华，方向不同整套手法不同。
2. **目标人群**：年龄 / 圈层 / 审美（Z 世代爱抽象梗图，银发族要更大字更直白）。
3. **竞品惯例**：同赛道视觉语言；决定跟随建立识别，还是反套路制造记忆点。
4. **文化语境**：地域与亚文化符号语义（某些动物 / 颜色 / 手势寓意），避免误读与冒犯。
5. **时间节点**：节日 / 热点 / 季节可借势，也可能需避嫌（如灾难期不宜喜庆）。

### 3. 关键方法与注意
- **做语义对照表**：把要用的核心符号（颜色 / 图形 / 词）列出来，标注在本文化下的含义，避免「我以为的」和「用户看到的」不一致。
- **禁忌优先于美观**：一个符号再好看，踩了文化 / 品牌禁忌就直接废。先列禁忌清单，再谈美。
- **调性要可验证**：品牌调性那 2~3 个词，要能用来判断「这个方案算不算」——不能只挂在墙上。
- **借势有度**：热点 / 节日可借，但要快、要贴、别硬蹭，避免翻车。

### 4. 与其他小节 / 层的衔接
- 同模块内：上下文 →「客观约束」（品牌合规、行业禁忌叠加红线）。
- 下一层：语义基调与禁忌直接喂给第 2 层——颜色（语义色板）、文字（语气与用语）。

- [ ] 是否画出了目标人群与审美习惯？
- [ ] 是否查了文化 / 亚文化符号语义，列清禁忌雷区？
- [ ] 是否看了竞品惯例，决定跟还是反？
- [ ] 是否考虑了时间节点（节日 / 热点）借势或避嫌？

# 小节 4 ｜ 客观约束

## 客观约束是什么（先对齐概念）

**客观约束（constraints）= 视用途而定的限制线。** 商用场景下它是不可逾越的硬红线（版权/合规/平台/无障碍），决定「能不能用 / 会不会出事」；个人练习 / 测试 / 自娱场景下则降级为轻量自查，不强制全套。

## ⚠️ 触发条件：先判定是否「商用」（决定红线强度）
- **默认＝轻量模式**：个人练习 / 测试 / 自娱 / 内部草稿。**不强制**全套红线——只需轻量自查：字体图片自己能用即可（不必查授权白名单）、对比度基本可读即可（不强制 WCAG）。
- **商用模式＝仅当需求明确说「商用 / 对外发布 / 赚钱 / 客户交付」才触发**：此时才强制执行完整红线卡（版权授权、广告法合规、平台审核规范、WCAG 无障碍全套）。
- 一句话判定：**需求没提「商用」→ 轻量；提了「商用」→ 严格**。本小节后续步骤的「必做项」一律按此切换。

五类红线：

| 类别 | 是什么 | 踩了的后果 |
| --- | --- | --- |
| 版权 | 字体 / 图片 / 音乐 / 视频 / logo 的授权 | 法律纠纷、索赔 |
| 合规 | 广告法 / 行业法规 / 数据隐私 | 下架、罚款、约谈 |
| 平台规则 | 各平台尺寸 / 格式 / 审核规范 | 不通过、限流 |
| 预算工期 | 能投入的成本与时间 | 做不完 / 砍复杂度 |
| 无障碍 | 残障友好（对比度 / 色盲 / 字幕） | 可用性缺失、合规风险 |

常见红线示例：

| 场景 | 典型红线 |
| --- | --- |
| 商用海报 | 字体需商用授权（思源 / 站酷等免费可商用）、图片需图库授权或自摄 |
| 电商主图 | 平台禁「最 / 第一 / 国家级」等绝对化用语、禁未授权品牌 logo |
| 金融 / 医疗广告 | 行业强监管，禁用承诺收益 / 疗效表述 |
| App / 网页 | WCAG 对比度 ≥ 4.5:1、色盲不能只靠颜色区分、动效需可关 |

## 在工作流中的位置（顺序执行）
- 上一步输入：需求 / 目标 + 本模块小节 1、2、3（载体、环境、上下文）
- 本步要做：列出所有不可逾越的硬限制——版权许可、合规要求、平台规则、预算与工期、无障碍规范，汇总成**红线卡**
- 输出给：第 2 层（在红线内选材、选字、配色，所有后续创作都被这张卡框住）

## 操作要点

### 1. 具体怎么操作（四步红线法）
> 步骤 1 / 2 / 4 在**轻量模式**下可简做或跳过，仅在**商用模式**强制；步骤 3（预算工期）两种模式都建议过一遍。

1. **列版权清单**（商用必做）：用到的字体 / 图片 / 音乐 / 视频 / 第三方 logo 是否都有授权？无授权的换免费可商用资源。→ 轻量模式：确认是自己能用的素材即可，不查授权白名单。
2. **列合规与平台红线**（商用必做）：广告法禁用语、行业限制、目标平台审核规范，逐条列出。→ 轻量模式：跳过。
3. **列预算与工期**（两种模式都做）：能投入多少、何时交付，决定复杂度上限（动效 / 3D 成本高要评估）。
4. **列无障碍要求**（商用必做）：对比度、色盲友好、字号下限、替代文本、动效节制。→ 轻量模式：做到「基本可读」即可，不强制 WCAG 4.5:1。

### 2. 客观约束五件套（每个设计必须确认）
1. **版权**：字体商用授权（思源黑体 / 站酷系列等可商用白名单）、图片图库授权或自摄、音乐 / 视频素材版权、第三方 logo 使用规范。
2. **合规**：广告法绝对化用语禁用（最 / 第一 / 国家级）、医疗金融等行业限制、数据隐私（不收集非必要信息）、必备标识（备案号 / 警示语）。
3. **平台规则**：各平台画布尺寸 / 格式 / 内容规范（小红书 / 抖音 / 微信）、审核红线词与图、电商主图规范。
4. **预算工期**：决定动效 / 3D / 实拍等重成本手法是否可行，交付时间节点。
5. **无障碍**：WCAG AA 对比度 ≥ 4.5:1、不只靠颜色传达信息、字号下限、替代文本、动效可关闭（前庭功能障碍友好）。

### 3. 关键方法与注意
- **红线卡先于美观（仅商用模式）**：先产出红线卡，再开始第 2 层创作。所有选材选字配色都在卡内。轻量模式无需此卡，凭手感即可。
- **建免费资源白名单（商用提效）**：常用可商用字体 / 图库 / 音乐列成白名单，下次直接取，省去每次查授权。
- **合规用语替换表（仅商用）**：把「最 / 第一 / 极致」等禁用语对应成合规表述（如「广受好评」），评审时直接替换。
- **无障碍是商用底线（轻量只求基本可读）**：商用模式对比度与色盲友好先做满再谈花样；轻量模式做到「基本可读」即可，不必卡 WCAG。

### 4. 与其他小节 / 层的衔接
- 同模块内：客观约束是场景层的收口，吸收载体 / 环境 / 上下文里涉及合规的部分。
- 下一层：红线卡是整个第 2 层及之后创作的边界框——在卡内选材、选字、配色。

# 小节 5 ｜ 审美意图卡（第 1 层收口 → 第 2 层方向盘）

> **为什么有这一节**：审美不是"做完再验收"的，而是"动手前先定向"。第 1 层的载体 / 环境 / 上下文 / 客观约束定清后，进第 2 层之前，先写一张卡把**审美方向**钉死——让感觉先行、规则后到。这样第 2–5 层不是在"避免错误"，而是在"朝一个明确的好看走去"。

## 卡片三要素（动手前必填）

1. **3 个主感觉词**（≤3，宁少勿多）：定稿时希望观者第一眼感到什么？每个词必须能落到第 2/3 层的具体手段（"高级"→ 克制配色≤3 色 + 大留白 + 细字重），不能只是形容词。
   - ⚠️ **必须翻译成参数**：每个感觉词至少翻译成 **2 个可测参数**（字号阶梯比 / 灰度层级 / 间距倍率 / 字重对比 / 细节密度）。映射表见 `references/审美精度标准.md` **A 段**——只填形容词不翻译，等于没填卡，落到第 3 层会滑回默认参数。
2. **1 个视觉对标**：一个**真实存在**的方向 / 作品（不是想象）。来源：`design-reference-sourcing` 抓回的参考、`taste-profiles` 的实例、或亲眼看过的东西。选完**先看再动手**。
3. **1 个破格点**：本轮**允许打破哪条默认规则**（"允许一个元素满屏出血""允许一束高饱和撞色""允许一处违反网格"）。破格点只能 1 个，其余规则照守——这是"有目的的意外"，不是失控。

> **方向 → 精度 → 记忆点**：本卡定**方向**；`references/审美精度标准.md` 保**精度**（数值不糊）；`references/惊艳手法库.md` 给**记忆点**（一轮最多 1 个破格）。三者各管一段，缺一段就会产出"能看但不好看"的东西。

## 与三种调用模式的关系

- 模式 1 领域适配：感觉词从载体 / 环境反推（广告牌 → "醒目·利落·远看可读"）；对标可查 `references/UI风格适配参考.md`。
- 模式 2 吸睛：对标从 `taste-profiles/` 选实例（先对照实例参考图）；破格点沿所选 profile 的 signature 走。
- 模式 3 AI自主：对标可跨领域选；破格点允许更大胆，但仍是"可命名的破格"。

### 两种输出形式（精简判定）

- **图表（默认）**：用户只给数据，或说"可视化/分析数据/做几张图/做个图表页"——产出单图或图表页。没有"报告"关键词时不得自行升级成报告。
- **报告（升级）**：只有用户明确说"报告/年报/月报/白皮书/调研一页纸/海报/brief/dashboard 报告"等完整叙事交付，才读报告模板、按场景选版式、单页聚合多图。

### 判定硬规则

- 有歧义仍选**图表**：只说"分析"但无报告关键词 → 先交付最强单图或 2–3 张证据图；可在文字中提示"如需完整报告可切换"，但不直接生成报告。（报告模式 ≠ "多画几张图"。）
- 报告内的图表仍遵守图表的数据契约：报告模板定整页结构，页内每张图独立选型。
- 语言：用户未指定时跟随输入语言；同版本内不混中英。

### 与五层衔接

- 形式判定是第 1 层场景的延伸（载体=图表页/报告页时触发）。
- 选图表 → 路由到子技能 `design-chart` 走完整方法（选型/编码/自检）；选报告 → 第 1 层先定版式，再逐图回 `design-chart`。
